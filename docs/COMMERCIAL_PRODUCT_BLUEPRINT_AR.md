# AI-Engineer — مخطط التحويل إلى منتج تجاري داخل AutoCAD وRevit

**التاريخ:** 2026-11-04  
**الحالة:** خطة منتج مقترحة، وليست وصفاً لميزات جاهزة أو موافقة هندسية على أي رسم.  
**مالك قرار المنتج:** Hamada Gamal.  
**الهدف:** تطبيق Windows يُثبَّت بواجهة محادثة داخل AutoCAD وRevit، قادر على القراءة والتحليل والاقتراح والتنفيذ المحدود بعد مراجعة المستخدم، مع اختيار مزوّد ذكاء اصطناعي وترخيص تجاري لجهاز نشط واحد لكل حساب.

## 1. نقطة الانطلاق والحدود

- AI-Engineer الحالي يضم لوحة AutoCAD، خدمة محلية، موصلات ومزوّدات OpenAI/Gemini/Codex/Ollama، وأعمال Revit 2024 تجريبية ومحدودة. وجود الشفرة أو تجربة ناجحة لا يعني جاهزية إصدار تجاري عام. يجب إعادة تدقيق السلوك والاختبارات على آخر نسخة قبل الإعلان عن كل ميزة.
- `docs/PRODUCT_VISION.md` يجعل AutoCAD أول منتج إنتاجي، وRevit موصلاً تالياً. طلب المالك الحالي يضيف واجهة داخل Revit أيضاً؛ لذلك يُبنى قلب مشترك من الآن، لكن يُطلق AutoCAD أولاً بعد بوابة قبول كاملة، ثم Revit بعد بوابة مستقلة. لا ننسب قدرة Revit إلى AutoCAD أو العكس.
- المقصود بـ«صلاحيات كاملة» هو **اتساع القدرات المصرح بها** وليس إعطاء النموذج وصولاً غير مقيد للملفات أو أوامر CAD أو النظام. النموذج يقترح، والبرنامج يتحقق من الأنواع والنطاق والاعتماد، والمستخدم يوافق على التعديل. لا تعطيل لبوابات المعاينة أو النسخ الاحتياطي أو سجل التدقيق.
- أوامر المستخدم والمستندات والرسومات تُعامل كمدخلات عمل؛ نصوصها ليست تعليمات برمجية ذات صلاحيات. لا تنفيذ لنص أمر خام من رد النموذج.

## 2. تجربة المستخدم المستهدفة

1. يثبت المستخدم حزمة موقعة؛ يفحص المثبّت وجود وإصدار AutoCAD/Revit المدعوم، ويثبت إضافة كل تطبيق على حدة، مع خدمة محلية مشتركة. لا يفشل التثبيت إذا كان أحد التطبيقين غير موجود؛ يعرض حالة كل موصل بوضوح.
2. يسجل ببريد موثق ويفعّل ترخيصه. يرى حالة الجهاز النشط وتاريخ انتهاء الاشتراك وإمكانية نقل التفعيل.
3. يفتح لوحة محادثة عربية/إنجليزية داخل التطبيق المضيف. يمكنه اختيار مزوّد واحد متاح للمحادثة أو تغيير المزوّد، مع إعداد مستقل لمفتاح كل مزوّد؛ لا يلزم إدخال مفاتيح الثلاثة. توضح الواجهة المزايا المدعومة وتكلفتها التقديرية وحدود البيانات التي سترسل للخارج.
4. يسأل سؤالاً عاماً أو يحدد رسماً/عناصر/نطاقاً صراحة. يعرض البرنامج ما يراه النموذج: اختيار العناصر، الخصائص، الطبقات، المقياس، والملفات المرفقة. يبدأ بالبيانات المنظمة؛ يلتقط صورة محدودة من الـviewport فقط عند حاجة واضحة وبعد مراجعة المستخدم للّقطة قبل إرسالها لمزوّد سحابي.
5. يستطيع طلب كشف أخطاء، حصر، حسابات، رسم أو تعديل. التحليل لا يغير الرسم. التعديل ينتج خطة بأسماء وIDs العناصر، الأبعاد، الوحدات، القيم قبل/بعد، النتيجة المتوقعة، ومصدر كل افتراض. تُعرض معاينة قابلة للمقارنة ثم موافقة واضحة على دفعة محدودة.
6. ينفذ الموصل عبر واجهة التطبيق الرسمية داخل Transaction/Undo مناسب، ويتحقق من النتيجة بعد التنفيذ؛ عند الفشل يُرجع التعديل أو يستعيد نسخة محفوظة ويعرض سبباً حقيقياً. يبقى المهندس مسؤولاً عن اعتماد التصميم النهائي، ويظهر نقص البيانات بدلاً من اختلاقها.

## 3. المعمارية المرجعية

```text
AutoCAD native palette (.bundle) ─┐
                                  ├─ authenticated localhost service ─ tool/capability broker
Revit native dockable pane (.addin)┘                     ├─ typed project model + calculation engine
                                                        ├─ plan / preview / approval / audit / recovery
                                                        ├─ provider adapters: OpenAI, Gemini, Claude, others
                                                        └─ licensing client ↔ HTTPS licensing service
```

- **AutoCAD:** إضافة .NET/Palette أصلية عبر `.bundle` وملف manifest، بواجهات AutoCAD المدعومة، مع مصفوفة إصدار منفصلة. لا أتمتة موس/كيبورد كمسار الإنتاج الأساسي.
- **Revit:** إضافة `.addin` وDockable WPF Pane. قراءات/تعديلات النموذج عبر Revit API و`ExternalEvent` على سياقه الصحيح، مع Transactions وRollback. لا وصول مباشر إلى نموذج Revit من خيط الشبكة أو النموذج اللغوي.
- **الخدمة المحلية:** تربط `127.0.0.1` فقط، مصادقة جلسة قصيرة العمر وقائمة قدرات/أوامر ذات أنواع، حدود زمن وحجم، حماية مسارات العمل، وسجل طلب/نتيجة. لا API أوامر مفتوح على الشبكة.
- **نموذج المشروع:** كائنات هندسية مشتركة (لوحات، قواطع، أجهزة، كابلات، دوائر، غرف/عناصر، مصادر الأدلة) مع IDs مرجعية ومصدر وقيم ووحدات؛ يحتفظ كل موصل بخريطة IDs إلى التطبيق المضيف. يراجع المستخدم أي اختلاف عند المزامنة.
- **الفصل:** نموذج الذكاء لا يقرأ ملفات المشروع أو يغيرها وحده؛ يحصل على سياق مُختار عبر broker، ويرسل طلبات أدوات محددة، والبرنامج يتحقق منها. الحسابات الهندسية الحاسمة تنفذ بمحرك حتمي واختبارات وأدلة كود/مصنّع محدثة، لا بذاكرة النموذج.

## 4. مزوّدو الذكاء والمفاتيح والخصوصية

- واجهة Provider مستقلة: `chat`, `structured_plan`, `tool_proposal`, `vision` اختياري، حدود الاستخدام، إلغاء الطلب، أخطاء موحدة. أي مزوّد لا يدعم قدرة يعلن ذلك ولا تُعرض له أداة وهمية. البدء بـ OpenAI API وGemini API وClaude API وفق العقود الرسمية وقت التنفيذ؛ إضافة غيرها عبر Adapter ومراجعة أمنية.
- كلمة **Codex** ليست مرادفاً لمفتاح API مستقل. يُعرض خيار OpenAI API للمزايا التي تدعمها واجهاته الرسمية؛ التكامل مع Codex app-server، إن كان مناسباً ومسموحاً تجارياً، مسار مختلف يحتاج تحققاً تعاقدياً وتقنياً. اشتراك ChatGPT لا يُفترض أنه يغطي استخدام API التجاري.
- نمطان تجاريان: **BYOK** (المستخدم يدخل مفتاحه وتُحسب رسوم المزود على حسابه) أو **Managed API** (الخادم التجاري يدير المفاتيح والفوترة والحصص). يمكن عرض الاثنين مستقبلاً، مع توضيح أن ترخيص AI-Engineer ورسوم مزوّد الذكاء منفصلان.
- لا يوضع سر مالك المنتج داخل DLL أو تطبيق العميل. مفتاح المستخدم في Windows Credential Manager/DPAPI حسب هوية المستخدم، ولا يظهر في السجل أو النسخ الاحتياطية. لو استُخدم backend للنداءات فالمفاتيح في مخزن أسرار خادمي، مع حدود معدّل وتكلفة.
- ملفات CAD/Revit قد تكون سرية؛ الوضع الافتراضي لا يرسل الرسم كاملاً ولا يلتقط الشاشة تلقائياً. موافقة إرسال سياق لكل مشروع/جلسة، معاينة للحمولة، حد أقصى للحجم، إمكان إخفاء أسماء/طبقات، سجل لما أُرسل، وسياسة حذف/احتفاظ. الصورة ليست بديلاً عن قراءة هندسية منظمة ولا تثبت الأبعاد وحدها.

## 5. نموذج الصلاحيات والتنفيذ

| مستوى | مثال | الموافقة |
|---|---|---|
| 0: محادثة عامة | شرح أو سؤال بلا رسم | فتح المحادثة فقط |
| 1: قراءة مختارة | عناصر محددة، حصر، لقطة محدودة | اختيار الرسم والنطاق ومراجعة الإرسال الخارجي |
| 2: إنشاء/تعديل محدود | إضافة بلوك، نقل عنصر، تعديل خاصية | خطة + معاينة + موافقة صريحة على دفعة محددة |
| 3: أثر كبير/صعب الرجوع | حذف، استبدال واسع، تغيير ملف مصدر، اعتماد حساب | موافقة مستقلة، نسخة احتياطية، تحقق واسترداد |

الموافقة مرتبطة بـ hash الرسم/النموذج والاختيار والخطة والإصدار ووقت انتهاء. أي تغير بين المعاينة والتنفيذ يلغيها. لا تُمنح موافقة دائمة لكل التعديلات. أوامر النظام والملفات الخارجية والتثبيت والنشر لا تُستنتج من محادثة الرسم، بل صلاحيات مستقلة ومحددة.

## 6. الترخيص التجاري والحسابات

**الهدف التجاري:** حساب موثق بالبريد، ترخيص أو اشتراك، وجهاز نشط واحد في الوقت نفسه، مع نقل ذاتي من جهاز إلى آخر. التفعيل ليس برقم نصي فقط؛ الرقم/الكود وسيلة ربط بحساب واستحقاق موقّع على الخادم.

1. ينشئ المالك تراخيص من لوحة إدارة HTTPS مع سجل إصدار/إلغاء ودور مدير منفصل. يربط المستخدم الكود ببريده بعد تحقق OTP أو رابط آمن، ويضيف MFA للإدارة.
2. يسجل العميل معرف جهاز مستعاراً ومستقراً نسبياً (hash مع salt خادمي لعدة إشارات؛ لا يعتمد على MAC وحده ولا يخزن بصمة عتاد خام). الخادم يحتفظ بـ **active lease واحد** لكل حساب/مقعد.
3. عند تفعيل جهاز جديد يُلغى lease السابق ذرياً على الخادم ويصدر رمز استحقاق موقّع وقصير العمر للجهاز الجديد. الجهاز السابق يخرج عند الفحص التالي/انتهاء الرمز؛ **الخروج الفوري من جهاز غير متصل بالإنترنت غير ممكن تقنياً**. تحدد السياسة مدة heartbeat وoffline grace بما يوازن العمل الهندسي مع منع المشاركة.
4. يمكن للمستخدم عرض الجهاز النشط، نقل التفعيل، فقد الجهاز، وإلغاء جلسة؛ ويملك الدعم مسار استرداد مدقق دون كشف كلمة المرور أو مفتاح API. تُحدَّد حدود نقل معقولة لمنع إساءة الاستخدام دون حبس عميل شرعي بعد تغيير الكمبيوتر.
5. حالات العميل واضحة: `trial/active/grace/expired/revoked/offline`. يوقف الترخيص أوامر المنتج المدفوعة حسب العقد، لا يفسد الرسومات أو يحذف بيانات المستخدم. لا يُعلن أنه «غير قابل للكسر»؛ التوقيع، تحقق الخادم، توقيع الملفات، وتحديثات آمنة تقلل القرصنة ولا تلغيها.
6. الموقع يحتاج حسابات، لوحة اشتراك وفواتير، استحقاقات، سياسة خصوصية وشروط استخدام، دعم، إدارة إصدارات، سجل تدقيق، نسخ احتياطي للخادم، مراقبة وتقييد الطلبات. لا تُخزن أسرار مزوّدي المستخدمين في قاعدة ترخيص بلا سبب.

## 7. الحسابات والمراجعة الهندسية

- كل نتيجة تعرض: المدخلات والوحدات، المعيار والنسخة والنطاق، معادلة/خوارزمية قابلة لإعادة التنفيذ، افتراضات، نتيجة، درجة اكتمال البيانات، وحدود التصميم. نصوص الكود/المصنّع تُجلب من مصادر رسمية أو مرخصة مع تاريخ ورابط/مرجع؛ لا تُعلن «مطابقة للكود» إن لم تتوافر الأدلة السارية.
- كشف أخطاء الرسم يفرق بين خطأ مؤكد، تعارض محتمل، وبيانات ناقصة. يقترح الإصلاح ولا يطبقه صامتاً. نماذج اللغة تشرح وترتب الأولويات؛ المحرك الحتمي والمهندس يقرران حسابات الحماية والكابلات والأحمال.
- لكل تعديل سجل before/after، معرفات العناصر، هوية المستخدم والمزوّد، hash الملف، الموافقة، النسخة الاحتياطية، خطوات التحقق ونتائجها؛ قابل للتصدير للدعم مع حجب الأسرار.

## 8. التثبيت والحماية والتشغيل

- مثبت Windows موقّع وتحديثات موقعة، فحص التوافق (Windows/AutoCAD/Revit/.NET)، تثبيت/إزالة آمنة لإضافات كل مضيف، خدمة محلية لا تبدأ بامتياز مدير إلا عند ضرورة موثقة. لا تعطيل لأمان AutoCAD أو Revit.
- مصفوفة إصدارات واختبارات لكل إصدار مدعوم، تشخيص اتصال واضح، rollback للتحديث، ترحيل إعدادات، نسخ احتياطي قبل أي تحويل بيانات. يعمل المحادثة/القراءة فقط في وضع انقطاع المزود إذا كان ذلك آمناً؛ يعتمد التنفيذ على الاستحقاق/الاعتمادات والسياسة.
- حماية ملكية المنتج عبر حقوق نشر واضحة، اتفاقية مستخدم، علامة تجارية عند ملاءمتها، توقيع ثنائيات، ترخيص خادمي، تقليل الكود الحساس في العميل، وإدارة ثغرات. تُراجع متطلبات Autodesk وشروط مزوّدي API والعقود والخصوصية محلياً مع مختص قانوني قبل البيع. إخلاء المسؤولية وحده لا يحمي من كل المسؤولية.
- مقاييس تشغيل قليلة وبموافقة المستخدم: أعطال/زمن استجابة/استهلاك الرموز على مستوى تقريبي، دون رفع ملفات الرسومات افتراضياً؛ حدود تكلفة وإنذارات وحصص لكل مستخدم/مشروع.

## 9. خطة التنفيذ القابلة للتسليم

كل خطوة أدناه تُعد «مكتملة» فقط بعد اختبارات آلية وتجربة حية على المضيف المعني، وتحديث دليل التشغيل، وتوثيق القيود. لا يبدأ جزء الكتابة قبل قبول القراءة والمعاينة له.

| ID | المرحلة | الناتج القابل للاختبار | التبعية/حد السلامة |
|---|---|---|---|
| C0 | تدقيق الأساس | جرد الميزات العاملة فعلياً، سجل أخطاء واختبارات، مصفوفة إصدارات | لا وصف تجاري قبل إثبات حي |
| C1 | عقد القلب المشترك | مشروع typed، سياق اختيار، أدوات محددة، جلسة محادثة ومراجعة egress | لا أوامر CAD خام |
| C2 | AutoCAD beta | لوحة أصلية، قراءة وتحديد، كشف أخطاء/حصر موثق، خطة ومعاينة وتعديل bounded/undoable | قبول AutoCAD حي + نسخ واسترداد |
| C3 | المزوّدات | OpenAI/Gemini/Claude مع إدخال مفتاح فردي، اختيار، إلغاء، حدود تكلفة، واجهة حالات | لا أسرار في repo/سجلات/ثنائيات |
| C4 | الحساب والترخيص | موقع وحساب موثق، لوحة إدارة، مقعد واحد، نقل، مهلة offline، فشل واسترداد | اختبار تزامن جهازين وانقطاع الشبكة |
| C5 | مثبت AutoCAD | تثبيت/ترقية/إزالة موقعة وتجربة جهازين نظيفين | لا ضرر برسومات المستخدم |
| C6 | Revit beta | Pane أصلية، سياق نموذج محدد، قراءة ومعاينة، ثم عمليات Revit API محدودة مع Transactions | بوابة قبول Revit مستقلة |
| C7 | قبول تجاري | أداء وأمان وخصوصية وفوترة ودعم ووثائق عربية/إنجليزية واختبار مشاريع حقيقية | مراجعة قانونية وهندسية قبل بيع عام |

**ترتيب MVP الموصى به:** C0→C1→C2→C3→C4→C5، ثم C6، ثم C7. بناء واجهة Revit بالتوازي ممكن هندسياً، لكن لا يُشحن كمكوّن كامل قبل اختباره. لا يبدأ التنفيذ على رسومات عميل قبل سيناريوهات الاسترداد.

## 10. قرارات مطلوبة من المالك قبل البناء التجاري

1. أي إصدارات AutoCAD وRevit ستُدعم عند الإطلاق؟ المرجع الحالي AutoCAD 2021 وRevit 2024؛ قد تلزم نسخ أحدث ومصفوفة منفصلة.
2. هل البداية ترخيص شهري/سنوي أم دائم بصيانة؟ كم مقعد لكل حساب؟ مدة grace عند انقطاع الإنترنت وحدّ نقل الجهاز؟
3. هل نموذج الدفع BYOK فقط أولاً أم اشتراك شامل استهلاك الذكاء؟ في BYOK تُدفع رسوم API مباشرة لمزوّد المستخدم ولا تُعد جزءاً تلقائياً من ترخيص المنتج.
4. أين تُستضاف خدمة الترخيص وما مناطق بيانات العملاء؟ ما المدة المسموح بها للاحتفاظ بالمحادثات/السجلات؟
5. ما أول 3–5 أوامر هندسية قابلة للتنفيذ تجارياً؟ لا يصح وعد «ارسم أي شيء» بلا حدود واختبار. يُفضل البدء بجرد عناصر، حصر، فحص تعارضات، إضافة/نقل رموز محددة، وحسابات موثقة.
6. ما سياسة مراجعة المهندس وتوقيعه للمخرجات؟ وما النص القانوني النهائي بعد مراجعة مختص؟

## 11. ملاحظات تسليم لأي مطور أو وكيل ذكاء لاحق
